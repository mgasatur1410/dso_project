# ADR-002 — Error Format RFC7807

## Context
Ошибки должны возвращаться в формате RFC7807 (application/problem+json) с маскированием деталей и correlation_id для трассировки.

## Decision
- Все ошибки возвращаются с type, title, status, detail, instance, correlation_id по RFC7807.
- Внешние детали ошибок маскируются (без внутренностей исключений).

## Alternatives
1. Legacy-кейс: возвращать просто code/message (проще, но не трассируется и не стандартизовано).
2. Возвращать только HTTP-статус (коротко, но неинформативно для клиента и слежения).

## Security impact
Снижается риск случайной утечки деталей реализации через сообщения ошибок, упрощается поиск и анализ инцидентов по correlation_id.

## Rollout plan
- Все ошибки обработаны по RFC7807
- Correlation_id проставляется для ошибок и есть в логах
- Покрыто тестами на json-формат и наличие ключевых полей
